# Development

## Intent and acceptance

Cork turns the existing Mac wallpaper into a wall for images and text notes. Success means importing a local image, choosing Tape, Pushpin, Polaroid or Frame, creating Flat or Sticky text notes, moving/resizing/rotating them, locking the desktop, and recovering the same arrangement after relaunch. A local MCP must expose that same model and return screenshots for agent-guided arrangement. Pinterest authentication and discovery stay with the existing Pinterest plugin.

The target is macOS 14+, pointer and keyboard input, one or more displays, all ordinary Spaces. Pictures stay below application windows and pass clicks through while locked. Edit mode temporarily brings pictures forward; Done puts them back. Full-screen apps remain unobstructed. The utility uses a native library/inspector, menus and AppKit desktop windows. It has no account, cloud service, telemetry or background network activity.

## Ownership and boundaries

- `CorkCore`: Codable values, geometry/arrangement, validated state mutations, atomic persistence, JSON values, local socket transport and MCP schemas.
- `Cork`: the main-actor app coordinator owns the board, undo history and windows. Asset decoding/copying and disk writes run through an actor. Every mutation is saved before a successful MCP response. Failed writes preserve the last committed state.
- `CorkMCP`: stdio JSON-RPC bridge. It forwards tools over a user-private Unix socket. No direct board-file writes and no listening network port. Multiple MCP sessions reach one app owner.

Coordinates are screen-local points from the upper-left of a full display. Item width/height describe the unrotated decorated print; rotation is clockwise in degrees. Display IDs come from CoreGraphics. Missing displays are mapped temporarily onto the primary display without discarding saved identity.

The implementation is original. Übersicht informs desktop-window behavior; PinMark informs the four physical image treatments and agent bridge. Source and documentation evidence, including reconstruction limits, are in [RESEARCH.md](RESEARCH.md). Cork does not embed either app or copy its artwork.

## Evidence plan

Build both executables in Swift 6 mode with the installed Command Line Tools SDK (full Xcode currently requires a license acceptance; no global settings are changed). Test geometry, input validation, atomic batch edits, undo, persistence, socket round trips and MCP lifecycle/errors. Exercise add → style → arrange → screenshot → undo → relaunch against a running isolated app. Inspect the four rendered styles, empty/populated library, locked/edit state and permission-denied recovery. Check native labels and keyboard access. Multi-monitor and macOS 14 behavior require matching hardware/runtime; do not claim those from the current single-host run.

## Decisions

Version 0.2 adds a per-display Cork wallpaper layer. With Hide Desktop Files enabled it sits just above Finder's desktop icon layer, and Cork prints sit above it. This hides visual icons and their mouse hit targets without moving files, changing Finder preferences or restarting Finder. Quitting or a process exit removes the owned windows and reveals the original desktop. The wallpaper layer consumes background clicks while files are hidden; Desktop files remain accessible through Finder and Open Desktop Folder. Custom images and videos are app-owned copies. Video loops are muted and pause for screen sleep, an inactive user session and Reduce Motion. The original macOS wallpaper setting is retained; choosing System or quitting returns to it.

`Board.desktop` stores icon visibility, new-image style and image/video selection, including paused state. Older v1 boards decode this optional field with defaults; image IDs, geometry and source URLs are preserved. Media validation/copying and PNG preview creation happen through the repository actor. Native wallpaper decoding happens off the UI actor, and app-owned tasks reject stale media loads. Native Login Items remain authoritative through `SMAppService.mainApp`; a saved Boolean does not stand in for an enabled login item. Quit waits for pending board saves.

Version 0.3 adds a separate local `PhotoCollection`, not hundreds of hidden wall items. Its atomic manifest retains source, board, descriptive tags, dominant palette, and explicitly curated mood memberships. Imports merge by stable ID and retain existing media. A failed batch leaves the catalogue unchanged and removes only its uncommitted copies. A previous complete catalogue supports corruption recovery. Catalogue failure does not discard or block the saved wall.

Dice selection and geometry are pure `WallRotation` logic with an explicit seed. A roll chooses one eligible mood (eight photos minimum), favors images absent from the current wall, and originally placed up to 11 pictures with independently mixed physical treatments (superseded by the greedy 0.4 packing below). All new captions are blank. It preserves notes and other displays, reserves the upper-left for widgets, rejects unusable space, and commits through the existing board transaction and undo history. Auto selection avoids the preceding mood when possible. The next-roll preference, current mood, seed, and exact result persist. No timer or external recommendation service is involved.

The native dice button, menu and Command-R call the same operation as `cork_roll_wall`. Optional written captions use macOS Marker Felt with a system-font fallback; empty titles render no caption. Collection metadata supplies library names independently of blank wall captions and is disclosed in the inspector. Personal Pinterest downloads, manifests and verification captures stay outside versioned assets. Collection copies use a 2048-pixel cap for fast local rolls; normal image imports retain the 4096-pixel cap.

Use SwiftPM, AppKit and SwiftUI, with no third-party runtime dependencies. AppKit owns the borderless desktop windows; SwiftUI owns the standard library and inspector. A Unix socket provides serialized live commands without a local web service or shared-file writers. Images are copied into app-owned storage so moving the originals does not break the wall. MCP image imports accept explicit absolute local file paths; the Pinterest plugin supplies those paths. Source URLs are attribution data, never executable instructions.

For screenshot verification, launch the app through LaunchServices (`open`), including `--env` overrides for an isolated board. A binary run directly from an agent host may inherit the host's screen-permission attribution. `CORK_APPEARANCE=light` or `dark` is a development seam for native appearance checks without changing the Mac's appearance preference.

## Version 0.4: minimize controls and greedy layout

Intent: one action sends minimizable application windows to the Dock, and another press leaves them there. A configurable global shortcut and the exact two-anchors/third-finger-down gesture share that action. Preserve all wall items, photo metadata, wallpaper, desktop icon coverage, login registration and saved preferences. Target remains native macOS 14+, Swift 6, one physical trackpad/display for host verification. New Accessibility access is a macOS boundary; no permission is granted automatically. Physical gesture and actual cross-app AX behavior require that access and matching input hardware. Tests cover detector transitions, rejected ordinary gestures, migration and persistence; native checks cover recorder, registration, collision recovery, denied permission, restart and installation.

`Board.desktop.controls` is optional for old boards and defaults to enabled ⌃⌥⌘M plus the anchored swipe. Carbon registers an exclusive virtual-key shortcut; a proposed binding is reserved before atomic persistence, so a conflict retains the previous binding and revision. Recording temporarily suspends it, and Escape or focus loss cancels recording. Activation refreshes actual AX trust without polling. No event tap or global key logging is used.

The AX actor sets only writable `AXMinimized = true`, skips already minimized/modal/unsupported windows, and reports partial failures. It never hides/unhides applications or restores windows. Individual AX messaging has a 0.2-second timeout and the operation has a four-second deadline. Owned tasks coalesce simultaneous triggers and stop on quit. Cork's miniaturizable library can minimize, while wallpaper and paper panels remain visible.

The exact trackpad gesture needs raw global contacts unavailable from view-scoped public AppKit touch events. `CorkInput` isolates an original, runtime-guarded private MultitouchSupport ABI binding. Compatible device enumeration is separate from contact monitoring; monitoring only runs with AX trust and an active, awake user session. A mutex protects C callback delivery; a system lock protects the Swift continuation. Each session creates a fresh bounded stream, and generation fencing rejects stale callbacks. Only transient finger IDs/positions reach the pure detector, with no input persistence. The keyboard remains independent if the private API is unavailable. This private dependency is unsuitable for an App Store build without replacement.

Greedy layout replaces cell-based dice placement with maximal empty rectangles. At each step it scores available photos by decorated, rotated fit, area, edge use, style variety and freshness within one curated mood. It considers six deterministic size/placement variants and favors coverage while penalizing the largest remaining rectangle. Size limits prevent a few huge prints with tiny leftovers. The number of pictures adapts to usable space, up to twenty; notes and other displays stay unchanged. The upper-left 40% × 20% of the safe area is reserved for the usual widget cluster; this is a conservative fixed reservation, not automatic widget detection. Images never crop or stretch. `Arrange → Fill Space` repacks existing images without adding/replacing content, keeping notes, nonselected items and other displays as obstacles. The dice additionally selects matching source aspect ratios from the pool. Pure packing runs in an owned background task before the same saved, revision-checked, undoable transaction. Independent obstacle-edge sweeps measure the largest empty rectangle in tests.


The refreshed collection groups by visual feeling across Pinterest boards, not by the board's subject category. Original source boards and provenance never change. On a sufficiently varied pool, the packer starts with four different sources, favors less-represented sources thereafter, and caps a source at `ceil(photoCount * 0.4)`. A bounded repack tightens the cap if fewer photos fit than initially planned. A custom collection with only one or two boards remains usable, without claiming additional source variety. Private curated memberships, descriptive tags and original palettes live in the app-owned catalogue; the authored manifest is in Cork's private Collections folder. Existing stable mood IDs are retained when names and descriptions are refreshed.


A shortcut configuration has an explicit completion path even when the board mutation is a no-op. Ordinary UI refreshes cannot clear the prepared binding while its save is suspended. Both success and rollback finish the reservation before the tool returns. Free-area sizing measures the union of maximal empty rectangles, so overlapping notes are counted once and offscreen notes consume no desktop space.

## Version 0.5 intent

A wall is one colour composition: select a complementary palette, choose a compatible high-resolution Pinterest wallpaper, and fill with varied, matching images. Fill Empty preserves existing geometry and adds photos in the remaining space; kept images also survive randomization. A saved widget checkbox removes the reserved widget corner and covers desktop widgets while Cork runs. Add a configurable global randomize shortcut (default ⌃⌥⌘R), independent of Accessibility. Preserve personal media, notes, source metadata, undo, crash-safe saves, login status and original desktop restoration. Automatic wallpaper changes are optional; explicit image/video/system choices disable automatic wallpaper replacement. Verify colour ranking and pixel eligibility, fixed geometry, rotated gap filling, source variety, widget layers, hotkey conflicts, legacy decoding and restart. Existing AX/Screen Recording limitations remain separate from these features.

`ColourScheme` and `SceneOptions` keep fourteen curated palettes separate from the ten semantic moods. Automatic selection derives a palette from retained photos when present, otherwise chooses a compatible mood palette. Dominant sRGB colours come from a bounded 64 × 64 sample and deterministic clustering; OKLab distance ranks photos without pretending to infer their subject. Background ranking additionally checks expressive hue coverage so a generic neutral image does not win every colourful scene. Curated mood membership, freshness, source diversity and decorated aspect-ratio fit still constrain selection. Colour matching is a preference, with a varied fallback when too few sources match closely.

`WallpaperCollection` is independently saved and recoverable. Imports measure real pixel dimensions, handle orientation, copy selected local files at up to 8192 pixels and compute their palette. Automatic selection excludes sources smaller than the display's native dimensions or requiring more than 40% cropping. The selected palette, wallpaper provenance, dimensions and photo composition commit in one board transaction. If no wallpaper meets the requirements, the background remains and Settings explains the fallback. The renderer keeps the previous prints while an asynchronous background load completes, then swaps the composition together.

`WallRotation.compose` serves both Roll Wall and Fill Empty. Fill Empty treats every existing item as an obstacle; rolling retains notes, other displays and `keepInPlace` images. The packer begins with retained source counts, excludes retained asset/source duplicates and fills maximal empty rectangles. All automatic arrangements leave kept images in place. Undo restores the complete scene, including its wallpaper and options. MCP undo accepts an expected revision so verification or an agent cannot accidentally undo a newer user change.

Widget hiding changes only Cork-owned windows. Public window owner, layer and bounds metadata identifies Notification Centre's desktop widget surfaces; titles and pixels are not inspected. On the verified host, widgets sit at desktop-icon level +2. With files and widgets hidden, the full wallpaper cover sits at +3 and prints at +4. With only widgets hidden, the base stays below icons and +3 wallpaper replicas cover just the detected widget footprints; video replicas share the base player. With widgets visible, their layer remains above the icon cover. Activation and Space changes refresh the footprint masks. Quitting removes all covers. No Finder, Dock or widget preferences are written. The layout's conservative upper-left reservation is omitted when widget hiding is enabled; detection is for masking, not arbitrary obstacle-aware layout.

The two global shortcuts share one Carbon event handler and dispatch by distinct signatures. Both proposed keys are reserved before asynchronous persistence; failure discards proposals and retains both active registrations. Recording suspends both keys and cancellation restores them. A no-op save still finishes configuration, while incidental refreshes cannot discard an in-flight reservation. Randomize is independent of AX trust; minimizing other applications retains its Accessibility requirement.

## Version 0.5.1: note participation and dominant wallpaper hue

Each Flat or Sticky note has an optional `includeInLayout` Boolean, exposed as **Include in layout** and MCP `include_in_layout`. Missing values preserve the prior checked behavior. Participating notes remain packing obstacles for Fill Space, rolls and Fill Empty; Gallery/Grid/Collage can arrange them alongside prints. An unchecked note retains its geometry through every automatic layout and consumes no packing space. `Board.itemsBackToFront` sorts overlay notes after all images regardless of z-index, so later imports and rolls cannot bury them. The ordinary saved board transaction provides persistence, stale-write protection and Undo/Redo. No global setting or extra window level is needed.

Wallpaper choice is provisionally made from the scene palette, then revalidated against the selected photographs before the same atomic commit. The first meaningful chromatic swatch among each image's three most prevalent colours supplies its dominant hue. When the photos share a clear family, coloured backgrounds must stay within 22.5° of that family; minority accents cannot override the dominant background. Neutral or broadly mixed photo walls prefer quiet backgrounds. Matching chromatic backgrounds receive a ranking preference over neutral fallbacks. This corrects the observed blue-photo/pink-purple-wallpaper pairing that could pass the previous broad preset-distance score. Native-resolution and crop limits remain unchanged.


## 0.6 — reactive layouts and external widgets

The saved item model now supports optional `hidden`, note `includeInLayout`/`matchSceneColours`/`matchedNoteColour`, and widget reference/state fields without replacing legacy boards. `Board.itemsBackToFront` filters hidden items and orders overlay notes above every photo. UI and MCP patches share `BoardLayout.applyingCoordinateEdits`; participating coordinate or occupancy changes repack the same photos around edited anchors, while hidden/overlay movement stays independent. X/Y sliders commit at the end of a drag. Native item rows expose visible/hidden state and an accessibility visibility action.

`DisplayAdaptation` persists last-known display geometry. Owned, generation-checked tasks coalesce real screen notifications for 120 ms, wait for ordinary saves, clamp fixed items and reflow photos on shrink. Growth fills around the current scene from the current mood with a logical-area density cap; notification count cannot grow the collection indefinitely. All board writes retain atomic save/recovery and Undo. Native testing exercised 1800 × 1169 → 1512 × 982 → 1800 × 1169: shrink retained all original IDs in safe bounds, and growth added five photos without changing any existing smaller-layout item.

`NoteColours` derives a pale readable paper tint from actual visible photo palettes only for opted-in notes. The manual note colour remains saved and returns when matching is disabled. Wallpaper selection validates the actual final photo hue family, and imported wallpapers can be retired with `automatic: false` without deleting media. Eight reviewed high-resolution Unsplash originals supplement the private Pinterest wallpaper catalogue; personal media remains outside versioned assets.

`WidgetRegistry` validates and copies bounded local HTML/JS/CSS packages. Stable provider/widget IDs and independent JSON state are stored in the existing board; provider metadata has its own atomic registry and previous backup. `WidgetPlacement` chooses unoccupied space around fixed items before reflowing photos, so repeated Add to Cork operations do not stack toys. Explicit coordinates remain caller-controlled. See [the widget contract](WIDGETS.md) for limits and a working counter provider.

`WidgetSurface` hosts a root-scoped, nonpersistent `WKWebView`, installs restrictive CSP and mandatory compiled network rules before loading, and rejects navigation, media access and file pickers. WebKit content rules use separate protocol patterns because its regex grammar rejects disjunctions. A live canary confirmed local code runs while fetch/image requests never reach a loopback test server and an outside fixture file cannot be read. [WebKit documents the supported content-rule grammar](https://webkit.org/blog/3476/content-blockers-first-look/).

Widgets remain interactive at desktop level when locked. An edit overlay receives drags only in Edit Desktop. Their state messages are bounded to 64 KB and debounced 150 ms in owned tasks, serialized with board work. Toy-local writes do not increase the layout revision or bury layout Undo, and Undo preserves the latest state for surviving widget IDs. Sleep/session/hidden state pauses surfaces; teardown removes message handlers. No app commands, shell, screenshots, credentials or arbitrary file API is exposed to widget JavaScript. MCP discovery now has 22 tools. The generic host works with Swingset and the independent counter example, without a hosted marketplace or new runtime dependencies.
